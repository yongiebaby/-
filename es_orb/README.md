# ES ORB（オープニングレンジ・ブレイクアウト）検証

ES 5分足（ATASエクスポート, 2020-01〜2025-12）で、OR終値ブレイク → 次足始値の成行順張りを検証するコード。

## 実行

```bash
pip install numpy pandas numba
python es_orb/run.py --out results part1.csv part2.csv   # zipも可。複数ファイルは時系列に連結
python es_orb/report.py --out results                    # CSVとreport.htmlを生成
```

## ルール

| 項目 | 内容 |
|---|---|
| OR | RTH(09:30 ET)開始から 5 / 15 / 30 / 60 分の高安 |
| シグナル | OR完成後の足の**終値**がORH超 / ORL未満。ヒゲだけ抜けた足は見送り、本数をカウント |
| エントリー | シグナル足の次の足の始値で成行 (+1tick) |
| 損切り | ブレイク足のlow/high・ブレイク足の前3本のlow/high（ETH足を含む）・OR中値・逆側OR。1tickバッファ、約定は1tickスリッページ |
| 損切り不成立 | 次足の始値がすでに損切りライン越え → 見送り、件数を記録 |
| 利確 | 実約定価格から 0.2 / 0.5 / 1 / 1.5 / 2 RR。指値でスリッページなし |
| 同一足で両方 | 損切り扱い、件数を記録 |
| 引け | 16:00 ETで成行決済 (1tick) |
| コスト | 往復$4、1枚 = $50/pt |
| 再エントリー | 1日1回 / 同方向のみ / 逆方向のみ / 両方可 × 上限 2・3・無制限。一度シグナルが出た側は終値がOR内に戻るまで無効（保有中のブレイクも同様） |
| 受付時間 | エントリー足の開始が 11:30 / 13:30 / 15:30 / 16:00 より前 |
| 除外日 | RTHの足が70本未満の日（祝日・短縮取引日） |

## 最適化（ウォークフォワード）

| ステップ | IS | OOS |
|---|---|---|
| 1 | 2020–2021 | 2022 |
| 2 | 2021–2022 | 2023 |
| 3 | 2022–2023 | 2024 |
| 4 | 2023–2024 | 2025 |

1. フィルターなしのベース 3,200 通り（OR 4 × 損切り 4 × RR 5 × 再エントリー 10 × 受付終了 4）をISで評価。
2. スコア1・スコア2それぞれの上位10件に、ブレイク足フィルター（値幅÷ATR20、値幅÷OR幅）とヒゲ本数フィルターのグリッド（3,000通り）を掛けてISで評価。
3. 候補全体で再度順位付けし、最良の設定をOOSに適用。

- スコア1 = 「ネット損益/最大DD」と「期待値(R)」のパーセンタイル順位の平均
- スコア2 = 「ネット損益/最大DD」と「勝率」のパーセンタイル順位の平均
- ISで30トレード未満の設定は対象外

## ファイル

- `data.py` CSV読み込み・RTH日単位の配列化・OR計算
- `engine.py` 1設定のシミュレーション（numba）
- `backtest.py` 指標・グリッド・ウォークフォワード
- `analysis.py` ヒゲ本数・時間帯・ブレイク足サイズ・異例カウントの集計
- `report.py` / `report_template.html` CSVとHTMLレポートの出力
